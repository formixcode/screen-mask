# screen mask

แผ่นครอบหน้าจอแบบโปร่งใส — ไว้หรี่/กรองส่วนของจอที่สว่างเกิน (เช่นชาร์ต TradingView พื้นขาว)
คลิกตรงไหนก็ลากได้ ย่อ/ขยายได้จากขอบ-มุม แล้วเลื่อนสไลเดอร์เพื่อปรับความทึบ

## ใช้ยังไง

- **สไลเดอร์** = ความทึบ 0-100% (0 = โปร่งใสสุด ยังเห็นจอข้างหลัง · 100 = ทึบทึบ)
- **ตัวเลข %** = ค่าปัจจุบัน
- **แถบหัว (ของโปรแกรมเอง)** มี 5 ปุ่ม เรียงจากซ้ายไปขวา:

  | ปุ่ม | ทำอะไร |
  |---|---|
  | `C` | Click-through — เปิด/ปิดโหมดคลิกทะลุ (ติด = พื้นปุ่มเป็นเหลือง) |
  | `T` | On top — เปิด/ปิดอยู่หน้าสุด (ติด = พื้นปุ่มเป็นเหลือง) |
  | `-` | ย่อหน้าต่าง |
  | `□` | ขยายเต็มจอ / กลับขนาดเดิม |
  | `X` | ปิด |

- **โหมดคลิกทะลุ (`C`)** = หน้าต่างยังบังจออยู่ แต่ "พื้นที่ว่าง" ของแผ่นคลิก/ลากผ่านไปโดนหน้าต่างข้างหลังได้ (เช่นลากชาร์ตใต้แผ่นกรอง)
  **ตอนเปิดโหมดนี้ ปุ่มบนแถบหัว (C/T/-/□/X + ลากย้าย), แถบสไลเดอร์ และขอบย่อ/ขยาย ยังกดได้ทั้งหมด** — จะทะลุเฉพาะพื้นที่ว่าง
  (มีคีย์ **`Ctrl+Alt+Shift+C`** เป็นทางลัดเปิด/ปิดโหมดด้วย) · ตอนเปิดอยู่มีข้อความเหลืองบอกสถานะบนแถบหัว

- **คลิกที่ไหนก็ลากย้ายได้** ยกเว้นแถบสไลเดอร์ (ไว้ปรับค่า)
- **ขอบ 8 px รอบใบ + มุมทั้ง 4** = จับลากเพื่อย่อ/ขยาย
- **เส้นขอบเหลือง** รอบหน้าต่าง = ขอบที่จับได้ (หัวหมุนสไลเดอร์ก็สีเดียวกัน)

## build

```
cargo build --release
```

ได้ไฟล์ที่ `target\release\screen_mask.exe` (ไฟล์เดียว ~145 KB ไม่ต้องลง runtime อะไรเพิ่ม)

## จุดที่ต้องระวังตอนแก้

- หน้าต่างเป็น **`WS_POPUP` ไม่มี `WS_THICKFRAME`** — ตั้งใจเป็นแบบนั้น: ถ้าใส่ `WS_THICKFRAME` เมื่อไร DWM จะวาดกรอบขาว/เทาหนาราว 6-8 px ทับขอบในตอนหน้าต่างไม่มี focus
  (`DWMWA_BORDER_COLOR` / `DWMWA_NCRENDERING_POLICY` ตอบ S_OK แต่คุมกรอบตัวนั้นไม่ได้)
  → การลากย้าย + ย่อ/ขยาย จึงทำเองในโค้ด: `WM_NCHITTEST` คืน `HTCLIENT` ทั้งใบ แล้วจัดการใน `WM_LBUTTONDOWN` / `WM_MOUSEMOVE` ด้วย `SetWindowPos`
  → สถานะการลากเก็บใน thread_local: `MODE` (0=ว่าง 1=ลากย้าย 2=สไลเดอร์ 3=ย่อขยาย) + `RZF` (bit 1=ซ้าย 2=ขวา 4=บน 8=ล่าง) + จุด/rect เริ่ม (`SX SY SL ST SR SB`)
- หน้าต่างต้องมี flag `CS_HREDRAW | CS_VREDRAW` ที่ class + สั่ง `InvalidateRect` ใน `WM_SIZE`
  ไม่งั้นลาก/ย่อขยายแล้วเส้นขอบเหลืองจะค้างซ้ำ (Windows ยืดภาพเดิม ไม่วาดใหม่)
- ทั้งหน้าต่างใช้ `WS_EX_LAYERED` + `SetLayeredWindowAttributes(alpha)` → ปุ่ม/ข้อความทั้งหมดจางตาม opacity ด้วยกัน
- ตำแหน่งสไลเดอร์แก้ที่ `TRACK_X / TRACK_Y / TRACK_H / THUMB` หัวไฟล์ (ปุ่มคิดตำแหน่งจาก `BTN_W * BTN_N` ชิดขวา)
- ต้องเป็น DPI aware (`DPI_AWARENESS_CONTEXT_PER_MONITOR_AWARE_V2`) ไม่งั้นพิกัดเมาส์/ขนาดหน้าต่างจะถูกย่อตามสเกลจอ (จอ 4K ตั้ง 120% จะอ่านขนาดผิดจากจริง)
- **ปุ่ม `C` (click-through)** = สลับบิต `WS_EX_TRANSPARENT` ใน `GWL_EXSTYLE` (ต้องมี `WS_EX_LAYERED` คู่กันอยู่แล้ว) แล้วตามด้วย `SetWindowPos(..., SWP_FRAMECHANGED | SWP_NOREDRAW)`
  → **สลับ "ตามตำแหน่งเมาส์" ไม่ใช่ใส่ค้างทั้งใบ**: เปิดโหมดแล้วตั้ง timer 25 ms (`TIMER_THROUGH`) → `GetCursorPos` → `ScreenToClient` → ถ้าอยู่บนโซนใช้งาน (แถบหัว / แถบสไลเดอร์ ±14 px / ขอบ 8 px) → **ถอด** บิต, ถ้าอยู่บนพื้นที่ว่าง → **ใส่** บิต ⇒ ปุ่มกับสไลเดอร์จึงกดได้ตลอดเวลา
  → ตอนบิตติดอยู่ `WM_MOUSEMOVE` / `WM_SETCURSOR` / `WM_NCHITTEST` จะไม่ถูกส่งมาที่หน้าต่างเราเลย (cursor กลับเป็นของหน้าต่างข้างหลัง = ถูกต้อง) — timer ยังทำงานปกติจึงรู้ตำแหน่งเมาส์ได้
  → **ห้ามกลับไปใช้ `WM_NCHITTEST` คืน `HTTRANSPARENT`** แทนวิธีนี้: ทดสอบจริง 6 ต.ค. 26 แล้ว **คลิกไม่ทะลุข้ามโปรแกรม** (ได้ `HTTRANSPARENT` ถูกต้องแต่หน้าต่างข้างหลังไม่ได้รับคลิก) — `HTTRANSPARENT` ใช้ได้เฉพาะหน้าต่างใน thread เดียวกันเท่านั้น
  → ตอน `MODE != 0` (กำลังลาก/ย่อขยาย/ลากสไลเดอร์) timer จะ **ถอดบิตเสมอ** ไม่งั้นเมาส์ที่ถูก `SetCapture` ไว้จะหลุดกลางทาง
  → `Ctrl+Alt+Shift+C` = global hotkey (`RegisterHotKey` + `WM_HOTKEY`) เป็นทางลัดสำรอง (อะไรที่กินคีย์นี้จะทำให้คืน 0 → ดูบรรทัด `RegisterHotKey ... ok=` ใน `screen_mask.log`)
